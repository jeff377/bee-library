# Bee.NET 4.33.0 — Detailed Release Notes

[English](4.33.0.md) ・ [繁體中文](4.33.0.zh-TW.md) ・ [← CHANGELOG](../../CHANGELOG.md)

This document is the detailed version of the `[4.33.0]` entry in [CHANGELOG.md](../../CHANGELOG.md). The main CHANGELOG lists one line per change; this file keeps the full narrative — the *why*, the constraints, and the design context behind each change.

> The server now owns every `DateTime` it saves. `FormBusinessObject.Save` no longer uses the `DateTime` values a caller sends: new rows get the server's UTC reading, existing rows keep what the database holds, and the framework stamps `sys_insert_time` and `sys_update_time`. With that in place the Connector stops converting a saved `DataSet` to UTC and converts only filter values. "Now" in expressions follows the side the `DataSet` lives on, and the audit trail returns a change as a `DataSet` and survives values it used to fail on. **The breaking changes ship as a minor under the pre-stable policy.**

## Breaking Changes

### `Save` does not use caller-supplied `DateTime` values

`FormBusinessObject.Save` calls the new `protected virtual NormalizeDateTimes` after `EnforceWriteScope` and before `DoBeforeSave`. For every `FieldDbType.DateTime` field the `FormSchema` declares — `Date` fields are not touched:

| Row state | What the field receives |
|-----------|-------------------------|
| Added | `sys_insert_time`, `sys_update_time` and any field without a `DefaultValueExpression` receive this save's UTC reading; a field with an expression is cleared so the expression fills it |
| Modified / Deleted | Both row versions receive the value stored in the database; a modified row's `sys_update_time` then receives the UTC reading |

A modified or deleted row that is no longer in the database aborts the save with `UserMessageException` before anything is written. An `UPDATE` no longer overwrites `sys_insert_time` from the payload.

**Why**: a client holds its `DataSet` in the user's time zone, and nothing in the payload says which zone a value is in. Converting it back to UTC on the way in was the Connector's job, and every gap in that conversion — a daylight-saving fall-back hour whose wall time maps to two instants, a modified row whose other edits were lost during the rewrite, a filter value that slipped past the guard — became a wrong value in the database. Having the server not read the values at all removes the class of problem instead of patching each instance.

This applies to every caller, including another business object calling `Save` in-process. The cost is that a user cannot edit a `DateTime` field directly. A BO that needs to accept one overrides `NormalizeDateTimes`: read the caller's value, call the base implementation, then write the value back converted to UTC. The authorization and write-scope checks have already run by then.

**Compatibility**: `NormalizeDateTimes` is a pure addition; the behaviour change affects every form with a `DateTime` field. See [ADR-032](../adr/adr-032-datetime-timezone.md) option 5 and D14.

### `IDataFormRepository.GetRowsByRowId`

Detail rows had no read-back method, so `IDataFormRepository` gains `GetRowsByRowId(tableName, selectFields, rowIds)`, which reads any table by `sys_rowid IN (...)` in batches. `DataFormRepository` implements it.

**Compatibility**: a new interface member is source- and binary-breaking for a type that implements `IDataFormRepository` directly. Types deriving from `DataFormRepository` are unaffected.

### The request direction no longer converts a `DataSet`

`PayloadZoneConverter.ToUtc` is renamed `IsolateRequest`. For a `SaveRequest` it deep-copies the `DataSet` and leaves the values as they are, restoring the caller's instance afterwards; for a `GetListRequest` it still converts the filter values from the user's zone to UTC. `DateTimeZoneConverter.UserToUtc(DataSet)` and `UserToUtc(DataTable)` are removed — keeping them would leave a way around "the server does not use the client's `DateTime`".

The `SaveRequest` `DataSet` is now copied even when the session has no time zone. The server rewrites the `DataSet` it saves in place, and on an in-process call without the copy that rewrite would land on the caller's own instance.

**Compatibility**: source- and binary-breaking for callers of the removed and renamed members; inside the framework the only caller is `ApiConnector.ExecuteAsync`. On the wire, the `DateTime` cells of a `SaveRequest` are no longer guaranteed to be UTC. See [ADR-032](../adr/adr-032-datetime-timezone.md) D3, D4 and D14.

### `DateTimeBasis`: "now" follows the side the `DataSet` lives on

Server-side `FormExpressionCalculator.ApplyFieldExpressions` and `ValidateRules` evaluated `Now()` in the session time zone and put the resulting wall time into a `DataSet` held in UTC: a stored value, and any rule comparing it with a cell, was off by the zone offset.

The new `Bee.Base.DateTimeBasis { UserZone, Utc }` settles it. "Today" always follows the user's zone; "now" follows the basis of the `DataSet` it goes into — the user's zone on the client, UTC on the server. `FrameworkClock.Now(string, DateTimeBasis)` is new, and a trailing `DateTimeBasis basis = DateTimeBasis.UserZone` parameter is added to:

- `IExpressionEvaluator.Evaluate` / `Evaluate<T>`
- `DynamicExpressoEvaluator.Evaluate` / `Evaluate<T>`
- `FormRowDefaults.Apply` / `DefaultForDbType`

`DataFormRepository.GetNewData` and the two server-side passes pass `Utc`; client preview passes `UserZone`.

**Compatibility**: source compatible — existing call sites compile unchanged. Binary-breaking: callers compiled against 4.32.0 must be recompiled, and an external `IExpressionEvaluator` implementation must add the parameter (a compile error, not a silent runtime difference). `FormRowDefaults` takes an optional parameter rather than a new overload because `RS0027` does not allow a longer overload beside an existing one with optional parameters. See [ADR-032](../adr/adr-032-datetime-timezone.md) D12.

### `AddColumn` no longer writes a clock default

`DataTableExtensions.AddColumn(name, FieldDbType)` stored the UTC reading at column creation in `DataColumn.DefaultValue` for `Date` and `DateTime`. That value masked `FormRowDefaults`, which skips a field that already holds a value:

- `GetNewData`'s `Date` default was today in UTC, not in the session's zone.
- `DefaultValue` travels with the table to the client, so a detail row added on the client received the server's frozen UTC reading from the moment the skeleton was built.
- An empty table built by `FormValueBinding.BuildEmptyDataSet` had the same problem.

**Compatibility**: a `Date` or `DateTime` column created by `AddColumn` now has `DefaultValue = DBNull` and `AllowDBNull = true`. A new row that does not pass through `FormRowDefaults` holds `DBNull` there and is rejected by the database's `NOT NULL` constraint on save. Blazor's `InitializeNewMaster` is such a path; its documentation already limits it to tests and offline preview.

### `IGetChangeDetailResponse.DataSet`

The interface gains a `DataSet` property — see [Added](#getchangedetail-returns-the-change-as-a-dataset).

**Compatibility**: source- and binary-breaking for a type implementing `IGetChangeDetailResponse` outside the framework; both framework implementations are updated.

## Added

### `GetChangeDetail` returns the change as a `DataSet`

`GetChangeDetail` returned only the flattened `Fields`, so a caller could not see the master–detail structure. The response now also carries a `DataSet`, shared by the three event kinds:

| Event | `DataSet` content |
|-------|-------------------|
| Insert | `Added` rows |
| Update | `Modified` rows carrying their original values |
| Delete | The record as it was before deletion (`Unchanged` rows) |

`Fields` is still filled. The `DataSet` is `null` for a legacy DiffGram with no schema, for a legacy `DeletedRow` marker, and for an empty or corrupt payload; an old delete record is returned as `Deleted` rows, unconverted. Its `DateTime` values are converted to the user's zone as for `GetData`; the time strings in `Fields` are still UTC.

The wire contract gains `dataSet?`. A client that does not know the member ignores it. See [ADR-040](../adr/adr-040-audit-trail-taxonomy.md).

### `DateTimeBasis` and `FrameworkClock.Now(string, DateTimeBasis)`

See [the breaking change above](#datetimebasis-now-follows-the-side-the-dataset-lives-on).

## Fixed

### Saving a modified row no longer loses its other edits

`DateTimeZoneConverter` rewrote a modified row's original version by calling `RejectChanges`, which reverts the whole row, and then restored only the instant columns' current values. Every other edit on that row was silently discarded. This had nothing to do with time zones: any form with a `DateTime` column was affected on save. The converter now captures both versions of the entire row before `RejectChanges`. The save path no longer runs this conversion at all (see above); the response direction keeps the fix.

### `DateTimeWireGuard` runs before time-zone conversion

`ApiConnector.ExecuteAsync` converted the filter tree first and ran the guard afterwards. Conversion sets `Kind` to `Unspecified` before shifting, so after login — whenever a user time zone was present — the guard only ever saw `Unspecified`, and a `Kind=Local` filter value passed. That is the "fix it up and let it through" behaviour [ADR-032](../adr/adr-032-datetime-timezone.md) D6 rejects. The guard now inspects the caller's original values before conversion.

**Behaviour change**: a caller passing a `Kind=Local` `DateTime` as a filter value after login gets `InvalidOperationException` instead of silent acceptance.

### Time fields written through `ToColumnValue` are fixed-width

`GridControl` cells and both heads' `FormDataObject.SetField` go through `FormValueBinding.ToColumnValue`, which wrote strings as they came, so `"8:30"` broke the time field's guarantee that lexical order is time order. Only `TimeEdit` and the Blazor time input padded. A field declared `Time` now goes through `CTimeString` and is written as `HH:mm`; unparseable input throws `FormatException`, so a grid cell keeps its previous valid value as `TimeEdit` does.

### Blazor time input keeps the previous valid value

`DynamicForm`'s `TimeEdit` branch passed `CTimeString`'s result straight to `SetField`, and `CTimeString` returns an empty string for invalid input, so one mistyped character (`"25:00"`) cleared the field. Blank input now writes an empty string, parseable input is normalized to `HH:mm`, and unparseable input is not written. The input uses `@bind:get` / `@bind:set` so a rejected entry is pushed back to the browser instead of lingering.

### SQLite form reads return `DateTime` columns

SQLite stores `Date` and `DateTime` as text, so the columns `DataFormRepository` read back were `string`. `DateTimeZoneConverter` only picks columns whose `DataType` is `DateTime`, so an in-process (local) call returned form time fields without the UTC-to-user conversion. Remote calls were not affected, because the wire rebuilds columns from their declared type.

A column declared `Date` or `DateTime` that holds `string` is now replaced by a `DateTime` column, keeping its `FieldDbType` marker (a `Date` column is still not shifted). Text that cannot be parsed throws `InvalidOperationException`; an empty string reads as `DBNull`. Saving writes the value through the driver according to the parameter type, as a remote call already did.

### Audit serialization failure no longer fails a committed write

The change audit is serialized after the database transaction commits. A field containing a character XML does not allow — a pasted U+0001, for example — made `AuditDiffGram.Serialize` throw: the data was written, yet the API reported failure, the audit was not recorded, and `AfterSave` / `AfterDelete` and plugins were skipped. For the deployment-level `CreateApiKey` the key was stored but its secret was never returned.

The whole post-commit audit step now runs best-effort: a failure is logged (prog id, operation, record key — no field values) and the operation completes. The payload writer also stops failing on those values: control characters and U+FFFE / U+FFFF are written as character references and read back as the original; CR and CRLF are no longer normalized to LF; a lone surrogate, which has no XML representation, is replaced by U+FFFD. Existing audit data is unaffected. See [ADR-040](../adr/adr-040-audit-trail-taxonomy.md) sections 6 and 8.

### Delete audit stores the full original record

`Form.Delete` deletes by `sys_rowid` without going through the `DataSet`, yet the delete audit marked every row of the pre-delete record `Deleted` and wrote the changes as a DiffGram — on the shared `context.Snapshot`. With auditing on, `DoAfterDelete` and `AfterDelete` plugins that read a field threw `DeletedRowInaccessibleException`; with auditing off the same code worked.

The record is now written unchanged under a new root, `AuditDeletedRecord`, and the snapshot is only read. `ChangeDiffGramReader` dispatches on the root and produces the same `Fields` output as before for deletes. Existing delete records are not migrated and read as before. See [ADR-040](../adr/adr-040-audit-trail-taxonomy.md) section 10.

**Downgrade**: a reader older than 4.33.0 does not understand the new root and reads one meaningless field from a new delete record; the stored data itself is complete.

### `FieldDbType` markers survive an XML round trip

`DataSet.ReadXml` restores the `msprop:Bee.FieldDbType` annotation as a string, and `GetDeclaredFieldDbType` accepted only the enum value, so a column read back from XML fell back to inference from its CLR type: `Date` became `DateTime` and `Time` became `String`. Handed to `DateTimeZoneConverter`, such a `Date` column was shifted like an instant. The method now also accepts the string form, but only a string exactly equal to a member name; numeric strings, comma lists and different casing or whitespace still count as unmarked. The framework's own XML read-back point (`ChangeDiffGramReader`) does not read markers and is unaffected.

### `sys_insert_time` is read-only in the default `AuditRule` form

`sys_insert_time` and `sys_update_time` are stamped by `Save`, so a form that declares them marks them `ReadOnly="true"`. The default `AuditRule` `FormSchema` and `FormLayout` now do. `FormField.ReadOnly` is copied to `LayoutField` only when a layout is generated, so an existing hand-written or previously generated layout must be updated by hand.

## Changed

### Documentation moves into language folders

Public documentation moves into `docs/en/` and `docs/zh-TW/`, with `docs/README.md` as the language entry page; `docs/zh-TW/` is the source and other languages are translations. The old `docs/<name>.md` and `docs/<name>.zh-TW.md` paths no longer exist, so links to them need updating. The positioning also changes from ERP to form-based enterprise information systems, with ERP kept as the complexity benchmark.

### Package icon

The NuGet package icon changes. Published versions keep their icon.

### `apps/Bee.Northwind`

The `AuditRule` `FormSchema` and `FormLayout` mark `sys_insert_time` read-only, matching the framework defaults.

## Upgrade notes

**Upgrade the server before, or together with, its clients.** A 4.33.0 server ignores the `DateTime` values in a save, so an older client that still converts them to UTC keeps working. A 4.33.0 client no longer converts them, and a 4.32.0 server would store the user-zone values as if they were UTC. Deployments whose sessions have no time zone are not affected.

**Forms that let users edit a `DateTime` field.** `Save` now replaces that value: new rows get the save time, existing rows keep the stored value. To accept the user's value, override `NormalizeDateTimes` in the form's BO: read the value, call `base.NormalizeDateTimes(context)`, then write the value back converted to UTC. `Date` fields need nothing.

**Direct implementations of framework interfaces** add the new members:

```csharp
// IExpressionEvaluator
- object? Evaluate(string expression, IReadOnlyDictionary<string, object?> variables, Type returnType, string timeZoneId = "")
+ object? Evaluate(string expression, IReadOnlyDictionary<string, object?> variables, Type returnType, string timeZoneId = "", DateTimeBasis basis = DateTimeBasis.UserZone)
- T Evaluate<T>(string expression, IReadOnlyDictionary<string, object?> variables, string timeZoneId = "")
+ T Evaluate<T>(string expression, IReadOnlyDictionary<string, object?> variables, string timeZoneId = "", DateTimeBasis basis = DateTimeBasis.UserZone)

// IDataFormRepository (types deriving from DataFormRepository need nothing)
+ DataTable GetRowsByRowId(string tableName, string selectFields, IReadOnlyCollection<Guid> rowIds)

// IGetChangeDetailResponse
+ DataSet? DataSet { get; }
```

**Removed conversion members.** `PayloadZoneConverter.ToUtc` becomes `IsolateRequest`; `DateTimeZoneConverter.UserToUtc` has no replacement, because the server no longer reads a saved `DataSet`'s `DateTime` values.

**Tables built with `AddColumn`.** A `Date` or `DateTime` column no longer defaults to the current time. Code that adds rows to such a table without `FormRowDefaults.Apply` must set the value, or the save fails on `NOT NULL`.

**Compiled dependents.** Assemblies that call `IExpressionEvaluator`, `DynamicExpressoEvaluator` or `FormRowDefaults` must be recompiled against 4.33.0.
