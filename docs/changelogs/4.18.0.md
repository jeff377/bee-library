# Bee.NET 4.18.0 — Detailed Release Notes

[English](4.18.0.md) ・ [繁體中文](4.18.0.zh-TW.md) ・ [← CHANGELOG](../../CHANGELOG.md)

This document is the detailed version of the `[4.18.0]` entry in [CHANGELOG.md](../../CHANGELOG.md). The main CHANGELOG lists one line per change; this file keeps the full narrative — the *why*, the constraints, and the design context behind each change.

> This release is the output of a full framework review rather than a feature cycle. The headline is the **`System.ExecFunc` dispatch surface**: two maintenance operations were reachable by anyone holding a valid access token — `UpgradeTableSchema`, which will drop and rebuild a table in whichever database the caller names, and `TestConnection`, which opens an outbound connection to whichever host and port the caller supplies. Both are now local-only, and the dispatcher's default for an unannotated handler flips from *allow authenticated* to **refuse**. A new build-time analyzer makes the omission that caused this impossible to repeat.
>
> Account lockout also changes state: a complete `ILoginAttemptTracker` implementation had been sitting in the repository unregistered, so an out-of-the-box deployment had no lockout at all. It is now registered by default. Alongside these, a version-numbering defect is corrected — the published 4.17.0 package carries `AssemblyVersion` 4.16.0.0; see [Upgrade](#upgrade).

## Breaking changes

### The ExecFunc dispatch surface

- **An `IExecFuncHandler` method with no `[ExecFuncAccessControl]` is now refused instead of treated as `Authenticated`.** The previous default is what made the two operations below reachable: the dispatcher only rejected the combination *required == Authenticated and current == Anonymous*, so an unannotated method sailed through for any signed-in caller. Fail-closed is what `ApiAccessValidator` already does on the BO axis; the ExecFunc axis was the inconsistent one. `Hello` on both the form and system handlers is now annotated explicitly so its existing behaviour is preserved rather than widened. (`e2c89452`)

- **`SystemActions.ExecFuncLocal`, `SystemApiConnector.ExecFuncLocalAsync` and `FormApiConnector.ExecFuncLocalAsync` are removed.** The business-object method these addressed was deleted on 2025-10-03, in the same commit that introduced `ExecFuncAccessControlAttribute` — local-only semantics moved onto the attribute and the wire action was left behind. Since `JsonRpcExecutor` resolves the action with `Type.GetMethod(action)`, every call through either connector has thrown `MissingMethodException` for ten months; the surface had no test coverage, which is why nobody noticed. When the public API baseline was captured in 4.16.0 it recorded this as a published API — a snapshot guards against *change*, not against something that was already wrong. (`50e9ec78`)

### Removed public API

- **`ISerializableClone` and `DatabaseSettings.CreateSerializableCopy()` are removed.** The interface's documented purpose was to deep-copy a cached object before a serialization pipeline that encrypts sensitive fields in place. **That pipeline does not exist**: `DatabaseSettings` never implemented `IObjectSerializeProcess`, and encryption is performed explicitly by `CacheDefineAccess` through `DatabaseSettingsCryptor`. Since `DatabaseItem.Clone()` copies `Password` verbatim while the cached instance holds it decrypted, the clone protected nothing. Its only real effect was to avoid flipping the serialization-state flag on a shared instance, and that is now achieved more directly — see [Security](#security). (`e0c072b5`, `d45b6b48`)

- **`DbParameterSpecCollection`'s two convenience `Add` overloads move to `DbParameterSpecCollectionExtensions`.** A collection may expose only one public `Add`: XmlSerializer's reflection-only path resolves the add method with a single `Type.GetMethod("Add")` and throws `AmbiguousMatchException` when several public overloads exist — a failure that appears on AOT targets such as iOS and never on the desktop. This was the only such violation left in the repository, and it survived because the analyzer enforcing the rule was not attached to `Bee.Db`. Call sites written as `collection.Add(...)` still compile unchanged; the break is binary, not source. The `DataRowVersion` optional parameter is split into two explicit overloads, because after the move both `Add` overloads have the same arity and RS0027 requires the one carrying optional parameters to be the widest. (`344839e7`)

## Security

- **`UpgradeTableSchema` and `TestConnection` are local-only.** Both hang off `System.ExecFunc`, which is `[ApiAccessControl(Public, Authenticated)]`, and neither declared an access-control attribute. `UpgradeTableSchema` reaches `TableUpgradeOrchestrator`, which falls back to *create shadow table → `DROP TABLE` → rename* when an `ALTER` is not viable, against whichever `DatabaseId` the request names. `TestConnection` accepts a caller-supplied `DatabaseItem` — a `Bee.Definition.*` type, so it passes the typeless allow-list and can be constructed entirely from the wire — and calls `connection.Open()` on it; with `ServerId` blank the connection string and provider come straight from the caller, turning the server into an outbound scanner whose response timing distinguishes open ports from closed ones, and with `ServerId` set the `{@DbName}` / `{@UserId}` / `{@Password}` substitution is an unescaped string replace that accepts injected connection-string parameters. Both now require `LocalOnly`, which places them alongside `SaveDefine` as in-process maintenance operations. (`e2c89452`)

- **Account lockout is enabled by default.** `Login` is the only credential-checking surface reachable anonymously, and all three lockout call sites short-circuited on a null tracker. `AddBeeFramework` now registers `LoginAttemptTracker` (5 attempts / 15 minutes) via `TryAdd`, so a host that supplies its own implementation still wins. This is a behaviour change for existing deployments — see [Upgrade](#upgrade). (`3ca48eff`)

- **`GetDefine(DefineType.DatabaseSettings)` no longer returns plaintext passwords.** The response was built from the process-wide cache instance, and that instance holds decrypted passwords because `GetDatabaseSettings()` runs `DecryptInPlace` on it. The BO now reads the definition file directly, where passwords are still `enc:` ciphertext. This also makes `GetDefine` match the contract it states for itself — serve the definition *as stored* — and, because the result is a fresh instance, removes the shared object that the deleted clone was nominally protecting. The change is made in the business object rather than in `CacheDefineAccess`: that class is the framework's general definition entry point with five default interface methods routing through it, and a class named for caching that silently bypasses the cache for one type is a trap for anyone who uses it directly. Nothing consumes the plaintext through this path — connection resolution and `DatabaseRepository.TestConnection` both call `GetDatabaseSettings()`, which is a separate abstract member. (`e0c072b5`, `d45b6b48`)

## Added

- **`ExecFuncAccessControlAttribute.LocalOnly`**, and an `InvokeExecFunc` overload taking `isLocalCall`. The original overload is kept and treats the call as remote, so binary compatibility holds. (`e2c89452`)

- **BEE3003 (`ExecFuncAccessControlAnalyzer`).** A public method on an `IExecFuncHandler` implementation must declare `[ExecFuncAccessControl]`; omission fails the build. BEE3001 could not cover this — it inspects public methods on `BusinessObject` subclasses, and handlers are not in that hierarchy, which is precisely the gap the two operations above fell through. Documented in [analyzer rules](../analyzer-rules.md). (`e2c89452`)

- **`DbParameterSpecCollectionExtensions`** — the relocated `Add` overloads, kept in the same file as the collection so the reason they are extensions stays visible. (`344839e7`)

- **The serialization analyzers now run on `Bee.Api.Contracts` and `Bee.Db`.** BEE4002–4006 are per-compilation rules (only BEE4001 reaches across assemblies), so until now they were silent for the wire DTOs in one project and the framework collections in the other — the gate existed but was not fully wired. `Bee.Api.Contracts` came back clean; `Bee.Db` surfaced the `Add` overloads above. (`344839e7`)

## Changed

- **`JsonCodec` shares its `JsonSerializerOptions` instead of constructing one per call.** `JsonSerializerOptions` is System.Text.Json's type-metadata cache; building a new one per call means a 100% contract-cache miss plus three converter allocations, on a path taken four times per request (request in and response out, on each end). Six `static readonly` instances now cover the three ignore-condition combinations across indented and compact output. The wire path (`Serialize` / `Deserialize` / `ToJson`) also switches to compact — indentation belonged only to `SerializeToFile`, which writes definition files for humans to read. The neighbouring `MessagePackCodec` had always used a static instance; the divergence dates from the mechanical Newtonsoft → STJ port, where per-call `JsonSerializerSettings` had been harmless. (`659325ed`)

- **`AssemblyVersion` and `FileVersion` are back in step with `Version`.** See [Upgrade](#upgrade) for what this means for 4.16.0 and 4.17.0.

## Fixed

- **Three shared collections that are read concurrently are now concurrent collections.** `DbProviderRegistry` and `DbDialectRegistry` are read-only after startup in production but not in tests, where registration and lookup run in parallel across classes — a resize during a concurrent read gives `IndexOutOfRangeException` or an infinite loop, a classic *green locally, red in CI* source. `ClientDefineAccess`'s cache documented that concurrent readers of one key share a single in-flight request, but `TryGetValue` followed by an indexer assignment is not atomic, and the fire-and-forget calls in `ListView` land their continuations on the thread pool. The cache is now `ConcurrentDictionary<string, Lazy<Task<object>>>`; the `Lazy` matters, because `GetOrAdd`'s value factory can run more than once under contention and for this cache that would mean the duplicate round-trip it exists to prevent. (`bb27e568`)

- **`SystemBusinessObject` no longer serializes a shared cache instance directly when serving `PluginSettings`.** It called `XmlCodec.Serialize(cached)` rather than the existing guarded path. `XmlCodec.Serialize` flips serialization state on the *source* object and propagates it into child collections, so it is not a free deep clone. (`11c106f2`)

## Upgrade

### ExecFunc handlers must declare access control

```diff
  public class MyExecFuncHandler : IExecFuncHandler
  {
+     [ExecFuncAccessControl(ApiAccessRequirement.Authenticated)]
      public void DoSomething(ExecFuncArgs args, ExecFuncResult result) { ... }
  }
```

Unannotated methods are refused at dispatch. BEE3003 fails the build first, so the omission surfaces at compile time rather than as a runtime rejection. For operations that should only run in-process, use `[ExecFuncAccessControl(LocalOnly = true)]`.

### `ExecFuncLocalAsync` call sites

There is nothing to migrate to, and nothing that worked to migrate *from* — any existing call has been throwing `MissingMethodException` since 2025-10-03. Delete the call, or move the operation to `ExecFunc` with `[ExecFuncAccessControl(LocalOnly = true)]` on the handler.

### `DbParameterSpecCollection.Add`

Source is unaffected — `collection.Add(name, value)` and `collection.Add(field)` still resolve, now to extension methods. Assemblies compiled against 4.17.0 or earlier must be recompiled.

### Account lockout

Existing deployments that upgrade will start locking accounts after five failed passwords in fifteen minutes. To keep the previous behaviour, register a no-op `ILoginAttemptTracker` before calling `AddBeeFramework` — the framework registers its own with `TryAdd`.

### Assembly version identity

`AssemblyVersion` and `FileVersion` were last bumped for 4.16.0 and did not move for 4.17.0, so **the published 4.17.0 package contains assemblies stamped 4.16.0.0** — the two releases are indistinguishable by assembly identity. 4.18.0 restores the convention (all three fields move together) and jumps straight to `4.18.0.0`; `4.17.0.0` never existed and will not be issued. 4.17.0 is not being re-released. Anything that keys off assembly version rather than package version needs to account for the gap.

## Retroactive note: `IExcelHelper` was removed in 4.16.0

`IExcelHelper` was deleted in `206d29ff`, part of 4.16.0, and never appeared in any CHANGELOG — the commit message itself said it had to be listed as a breaking change, and that step was skipped. The entry has now been added to the [4.16.0 notes](4.16.0.md) where it belongs. Recording it here as well because a reader who already has 4.16.0 has no reason to revisit its notes.

This was found by the same review that produced this release, together with the fact that two maintenance documents described the gap as closed. Both have been corrected. `IEvictableCache`, which those documents named alongside it, *was* recorded correctly in 4.16.0.
