# Bee.NET 4.21.0 — Detailed Release Notes

[English](4.21.0.md) ・ [繁體中文](4.21.0.zh-TW.md) ・ [← CHANGELOG](../../CHANGELOG.md)

This document is the detailed version of the `[4.21.0]` entry in [CHANGELOG.md](../../CHANGELOG.md). The main CHANGELOG lists one line per change; this file keeps the full narrative — the *why*, the constraints, and the design context behind each change.

> This release came out of a framework-wide review rather than a feature plan, which shows in its shape: no new capability, a lot of things that were wrong in ways nobody had hit yet.
>
> The centre of gravity is concurrency. Four separate places assumed one user, one request, or one caller, and each of them is reachable by an ordinary deployment serving several people from one process. Around that sit a batch of removals and renames — all source-breaking — two mechanisms that were declared in a contract but never actually wired up, and three performance fixes where the cost tracked the wrong quantity.

## Security

### The `EXEC` string literal that was missed

SQL Server's "drop the column's default constraint" path builds a batch and runs it through `EXEC('...')`. Inside that literal, bracket-quoting an identifier is not enough — a single quote in the name still terminates the surrounding literal. The two literals beside it in the same method already escaped for that; this one did not.

Reachability is narrow: it is on the schema-upgrade path, which is `LocalOnly`, so the table name comes from a definition file rather than from a request. It is fixed because "narrow" is not a property that survives refactoring.

### `ApiKeyCache` cached attacker-chosen misses for five minutes

The cache's key is whatever identifier the caller put in the `X-Api-Key` header, and the gate runs on every request, so **every negative entry is attacker-chosen** — and the cache has no size limit. Five minutes of retention per random identifier is a memory lever with no matching benefit.

Negative caching is kept, at one minute, because it does help the case it was written for: a misconfigured client retrying one revoked key. It never helped against probing with *random* identifiers, since each distinct one reaches the database exactly once regardless of how long the miss is retained. The original justification had this backwards, and the code comment is corrected along with the value.

## Concurrency

### Per-session client state was process-wide

`ApiClientInfo.ApiEncryptionKey` and `UserTimeZoneId` were static. In `BeeBlazorProviderMode.Remote`, that means the most recent login wins: an earlier user's `Encrypted` requests are then encrypted with someone else's session key, the server's HMAC check fails, and that user is locked out until they sign in again.

One premise needed correcting first: the three statics on `ApiClientInfo` are not the same kind of thing. `ApiEncryptionKey` and `UserTimeZoneId` are per-user; `ApiKey` is per-deployment — it is read from configuration and identifies the application, not the person. Moving that one too would have been wrong, not safer.

The fix introduces `ApiSessionContext` to hold the two per-user values, with a shared `Ambient` instance. `ApiConnector` and the three concrete connectors each gain a **constructor overload** that takes one — deliberately not an optional parameter on the existing constructor, which is a binary-breaking change (4.20.0's `FormLiveComputation` was exactly that shape). A connector constructed without a session falls back to `Ambient`, so a single-user host behaves bit-for-bit as before. `BeeApiConnectorFactory` moves from singleton to **scoped** and takes a scoped context; its method signatures do not change, so call sites need no edit.

Passing `null` for the session throws rather than silently falling back to `Ambient`. A silent fallback would turn a misconfigured multi-user host into one that appears to work while sharing a key, which is the failure this change exists to prevent.

The rejected alternative was a process-wide dictionary keyed by access token. That replaces process-wide mutable state with a process-wide mutable *map* — the same shape, plus the question of who clears it, which is exactly where the unbounded lockout map came from.

### A cold cache key was built once per caller

`ObjectCache<T>.Get` and `KeyObjectCache<T>.Get` were read-create-write over a provider with no atomic get-or-create. Several requests reaching a cold key therefore each built their own object — each deserialising the same definition file, or issuing the same query.

The wasted work was the lesser half. **The duplicate instances were the real defect**: `SessionInfo` is cached this way, so `EnterCompany` performed through one instance was invisible to a request holding another, and resolvers that detect a reload by reference comparison read a duplicate as a change that never happened.

De-duplication is per key and holds only while a creation is in flight, so nothing accumulates for caches keyed by an access token — which matters, because those keys are as numerous as sessions.

### `EnterCompany` published a company before it had resolved it

The session object is shared by every concurrent request on the same access token, and `CompanyId` and `Roles` are the two inputs authorization reads. `EnterCompany` interleaved its writes with its lookups, leaving a window that spanned three database-capable calls in which a parallel request could authorize against the *new* company holding the *previous* company's roles.

Roles, capabilities and record-scope identity are now all resolved first, and written to the session together.

### Two more places that handed out or rebuilt shared definition state

`FormTable.RelationFieldReferences` built its reverse index behind an unguarded null check. Two requests touching the same cached schema could build it twice and receive different instances — and the builder's validation exception could surface from what looks like a plain property getter.

`FormDefinitionLoader.GetLocalizedSchemaAsync` returned the shared cached schema when no language was given, despite documenting that the cached instance is never handed out. `CultureInfo.InvariantCulture.Name` is the empty string, so that was the common path, not an edge case.

Both are instances of the rule in [Definition Data Immutability After Init](../development-constraints.md): everything reached through `IDefineAccess` is a process-wide shared instance, and a caller that mutates one leaks across sessions.

## Breaking changes

### A batch of public surfaces with no consumer

A symbol-level scan over the repository found no fully dead *types* — `IDE0051` / `IDE0052` with `TreatWarningsAsErrors` already hold that line for private and internal members. What it did find was public API that nothing reaches:

- **`Bee.Base.MemberPath`**, **`Bee.Base.ConnectionTestResult`** — no reference anywhere, no documentation.
- **`DataTableExtensions.NormalizeDateTimeMode(DataSet)`** — a redundant overload; the `DataTable` one is still in use.
- **`Bee.Api.Core.Registry.ApiContractRegistry`** — `Register<>` was never called, so the map was permanently empty, and every payload paid for a `GetInterfaces()` loop to consult it. The job it advertised, turning a business object's plain result into an API type, is what `ApiOutputConverter` already does. This was not a preserved extension point; it was a superseded duplicate.
- **`Bee.Api.Core.Messages.ApiErrorInfo`** — `JsonRpcError` replaced it as the wire's error shape. Its only remaining sign of life was a test that constructed it and read the fields back: enough to show as covered, not enough to show as used. It was also registered as a wire contract while being unreachable from the wire type closure, which is why the drift gate did not flag it.
- **`Bee.Api.Core.Messages.ApiCallContext.ShouldValidateEncoding`** — a computed property with no callers. `IsLocalCall`, which it negated, is unchanged.
- **`Bee.Definition.Settings.AuditLogOptions.ExecEnabled`** — a shipped configuration contract with no reader. The execution axis it advertised was never implemented, so a deployment reading its XML doc would have believed a switch was in effect that did nothing. Its five sibling flags each have a real consumer, and the architecture overview's "six-axis data trail" is corrected to five — which is what it actually listed.
- **`Bee.Db`'s five `Dml` interfaces** (`IFromBuilder`, `ILimitBuilder`, `ISelectBuilder`, `ISortBuilder`, `IWhereBuilder`) — each had exactly one implementation and no consumer referenced the interface, so implementing one achieved nothing. The concrete builders are unchanged. `IFormCommandBuilder` and `IParameterCollector` stay: those are consumed as types.

### The audit and definition axes leave the business-object interfaces

`ILogBusinessObject` and the `CreateLogBO` extension are removed, as are `ISystemBusinessObject.GetDefine` and `SaveDefine`.

An axis interface exists for one reason: so that one business object can call another. Querying the audit trail is not something a business object does to another business object, and neither is reading a definition — that goes through `IDefineAccess` directly.

**The public methods stay on the concrete business objects**, so what `JsonRpcExecutor` exposes over the wire does not change. A remote caller sees the same methods; only the in-process interface surface shrinks.

The reverse decision was made for `Login`, which stays on `ISystemBusinessObject`: a background job signs in under some identity to establish a connection and then acts as that user, so it does have a genuine internal caller. The two surfaces are independent — `[ApiAccessControl]` describes what external callers may reach, an axis interface describes what internal callers may reach, and neither implies the other.

### Three public types renamed away from collisions

| Before | After |
|--------|-------|
| `Bee.Definition.Identity.IAuthorizationService` | `ICompanyAuthorizationService` |
| `Bee.ObjectCaching.Services.AuthorizationService` | `CompanyAuthorizationService` |
| `Bee.Base.Tracing.TraceListener` | `TraceDispatcher` |

The old names collided with `Microsoft.AspNetCore.Authorization.IAuthorizationService` — which an ASP.NET Core host has in scope by default — and with `System.Diagnostics.TraceListener`.

Both collisions surfaced as `CS0104` at the one place that holds both namespaces at once: where a consumer registers the framework's services. That is not a coincidence, and it is why a name that looks fine inside the framework can still be the wrong name to publish.

**There is no type forward.** The new names also make the pair with `IDeploymentAuthorizationService` read correctly: one authorizes inside a company, the other against the installation. `SysInfo.TraceListener` and `ITraceListener` keep their names — neither collides with anything.

### `isLocalCall` no longer defaults to `true`

`IBusinessObjectFactory.CreateBusinessObject` and the `CreateFormBO` / `CreateSystemBO` extensions drop the default. A local call bypasses `ApiAccessValidator` outright, so the two-argument form silently produced a business object with no access checks — and that is the shape a host writing its own dispatcher reaches for first.

The business-object constructors keep their default for now. Constructing one directly is a more deliberate act than calling a factory, and changing it would touch every direct instantiation.

### `SerializableData*` become internal

The five `MessagePack.SerializableData*` types (58 public API entries) are the wire's own intermediate shapes for `DataSet` and `DataTable`, reached only by the formatters beside them. [ADR-037](../adr/adr-037-wire-explicit-registration.md) already made 24 of the 28 types in that folder internal; these were the remaining opening, and nothing outside `Bee.Api.Core/MessagePack/` referenced them.

### `StringUtilities.IsEmpty(object?)` → `IsEmptyText`

The two `object?` overloads stringify the value and then test the text, which is a different question from `ValueUtilities.IsEmpty(object)` — the two disagree for `Guid.Empty` and `DateTime.MinValue`, and the old names gave no hint which one a call site meant. The string overloads keep their names; the framework had one affected call site.

## Declared but never wired up

Both of these were written down as contract, and both had no implementation behind them. Neither is a regression introduced this cycle; they are gaps that a review found by reading the contract and then looking for the code.

### Company number formats applied to nothing

`NumberFormatApplier` stopped running when an earlier release removed the server-side bake, with a note that the consuming side would take it over. The consuming side never did — so company-level number formats had no effect on any head, quietly, for several releases.

`FormDefinitionLoader.GetLocalizedSchemaAsync` now applies it on both of its paths, including the early return for an empty language. The company comes from the new `CompanyAccessor` init property, which takes a **delegate rather than a value** because the entered company changes over a session's life. The Avalonia and Blazor heads both benefit without changes of their own.

### `-32002` and `-32003` were never thrown

[ADR-012](../adr/adr-012-session-company-context.md) published `CompanyNotEntered` (`-32002`, HTTP 409) and `CompanyAccessDenied` (`-32003`, HTTP 403) as part of the front-end contract in 4.4.0. Nothing in the framework ever threw them.

`EnterCompany` threw `InvalidOperationException`. `RepositoryDatabaseRouter` went further and wrote the error code's *name* into the message string — `throw new InvalidOperationException("CompanyNotEntered")` — with a test pinning that string. Both types are in the BCL allowlist `IsUserFacingException` reads, so both were mapped to `UserMessage` (`-32099`). The visible result: a user who opened a form without entering a company got a dialog reading "CompanyNotEntered", and the front end had no code to route on.

Each now has its own exception type (`Bee.Base.Exceptions.CompanyNotEnteredException`, `CompanyAccessDeniedException`), its own `MapException` branch, and its own reconstruction on the client.

**This changes the error code a front end receives** for those two conditions, from `-32099` to `-32002` / `-32003`. A client that matched on the message text will stop matching; that is the point.

## Performance

### Expression evaluation is 4.7× faster

Each evaluation handed the engine every column in the row rather than the ones the expression references, so the cost tracked the **column count** instead of the expression. Measured over 30 columns / 5 computed fields / 1000 rows: 57.2 ms → 12.2 ms.

### Permission lookups no longer track deployment size

`CompanyRolePermissions` is an immutable snapshot held in a process-wide cache, and its grant count is roles × models — thousands to tens of thousands in an ERP. Every check scanned all of them. The indexes are now built once at construction, so a lookup costs O(roles the user holds) rather than O(grants in the company): at 200 roles × 100 models, 23.4 µs → 0.08 µs, and flat as a deployment grows.

### An unchanged row carried its values twice

Both the MessagePack and the JSON writer sent Current *and* Original for `Unchanged` rows, while both readers restore that state from Current alone. And `DataFormRepository.GetData` calls `AcceptChanges()` before returning — a behaviour written into the `IGetDataResponse` contract — so **every row read from the database is Unchanged**. Payload and serialisation cost for a read were both double what they needed to be.

The reader side is unchanged and was already Current-only, in this version and in previous ones, so the smaller payload is understood by an older client as well.

One test asserted the old behaviour, named for it. That was a defect written down as a specification; it is reversed, and the round-trip test that covers the actual requirement was untouched and still passes.

## Fixed

### `WhereBuilder` lost `SecondValue` and `IgnoreIfNull`

When a query carried a `selectContext` and a condition's field name had to be rewritten, the rewrite dropped two properties. A `BETWEEN` lost its upper bound, and an `IgnoreIfNull` condition became `= NULL` — never true in SQL, so the query silently returned nothing instead of ignoring the condition.

### Three `catch` blocks that swallowed everything

The client's endpoint probe treated any fault as "server unreachable" and sent the user to the connection-setup view. The cache's file-watch token treated any fault as "no known write time". The `DataTable` JSON converter treated any fault as "leave the value as-is". Each now catches only the failures it was written for; anything else surfaces instead of being reported as something it is not.

### Five library `await`s resumed on the caller's context

`ConfigureAwait(false)` was missing on five `await`s that sit on the path a UI host reaches through `JsonRpcExecutor.Execute`, which blocks on the asynchronous core — resuming on a captured `SynchronizationContext` there is the classic deadlock. The surrounding code already followed the convention. `Execute` now documents that it blocks and points asynchronous callers at `ExecuteAsync`.

### `DatabaseSettingsChanged` fired on every load

Its only publisher was the settings cache's load path, and `DbConnectionManagerService` clears its connection cache in response — reached from inside its own `GetOrAdd` value factory, so every first settings miss discarded every connection entry built so far. It now fires on a genuine reload, which is what carries an external edit through to the connection cache. `DbConnectionManagerService` also implements `IDisposable` and unsubscribes: a static event holds its subscribers for the life of the process.

## Upgrade

Renames — mechanical, no behaviour change:

```diff
- Bee.Definition.Identity.IAuthorizationService
+ Bee.Definition.Identity.ICompanyAuthorizationService

- Bee.ObjectCaching.Services.AuthorizationService
+ Bee.ObjectCaching.Services.CompanyAuthorizationService

- Bee.Base.Tracing.TraceListener
+ Bee.Base.Tracing.TraceDispatcher

- StringUtilities.IsEmpty(object?) / IsNotEmpty(object?)
+ StringUtilities.IsEmptyText(object?) / IsNotEmptyText(object?)
```

Requires a decision rather than a substitution:

- **Every `CreateBusinessObject` / `CreateFormBO` / `CreateSystemBO` call site must now state `isLocalCall`.** Pass `false` for anything reached from a request; `true` bypasses `ApiAccessValidator` entirely.
- **If you called `CreateLogBO` or `ISystemBusinessObject.GetDefine` / `SaveDefine`**, go through the concrete business object, through `IDefineAccess`, or over JSON-RPC — the methods themselves are unchanged.
- **If your front end handles `-32099` for "no company entered"**, add `-32002` and `-32003`. The old behaviour matched on message text; the new codes are what [ADR-012](../adr/adr-012-session-company-context.md) specified.
- **If you construct connectors in a host that serves several users from one process**, pass an `ApiSessionContext` per user. Omitting it shares `Ambient`, which is correct only for a single-user host. Blazor Server hosts using `BeeApiConnectorFactory` get this from the scoped registration with no code change.
- **If you referenced `ApiErrorInfo`**, use `JsonRpcError`.

No coordinated deployment is required: the wire change removes a value that no reader ever consumed, in either direction.
