# Bee.NET 4.32.0 — 詳細變更說明

[English](4.32.0.md) ・ [繁體中文](4.32.0.zh-TW.md) ・ [← CHANGELOG](../../CHANGELOG.zh-TW.md)

本文件是 [CHANGELOG.zh-TW.md](../../CHANGELOG.zh-TW.md) 中 `[4.32.0]` 條目的詳細版本。主 CHANGELOG 每項變更一行；本檔保留完整敘述——每項變更背後的**原因**、限制與設計脈絡。

> 數量與重量的小數位數改為只看單位。標成 `Quantity` 或 `Weight` 的欄位必須綁定 `UnitField`，公司不再提供這兩類的位數：公司有本幣可以退，但沒有預設單位。這讓單位那一側對齊金額依幣別解析的作法。**兩項破壞性變更依 pre-stable 政策以 minor 發佈。**

## 破壞性變更

### 數量與重量欄必須綁定單位

標成 `NumberKind.Quantity` 或 `NumberKind.Weight` 的欄位，必須在 `FormField.UnitField` 指定存放其單位的欄位。不需要單位的數值——單位隱含在語意裡的計數——是一般數值欄位，不標 `NumberKind`。

**為何這樣改**：金額與數量過去沿著兩條看似平行、實際退到不同東西的遞補鏈解析位數。金額那條每一步拿到的都是一個幣別代碼——欄位的 `CurrencyField`、主檔列的 `sys_currency`、公司的 `DefaultCurrency`——公司只決定「用哪個幣別」，位數由幣別主檔決定。數量那條則從 `UnitField` 直接退到公司的小數位數，由公司直接決定位數。單位沒有東西可以扮演本幣的角色：公司有預設幣別，但沒有預設單位，同一張訂單可以同時賣 PCS 與 KG。幣別遞補鏈能帶到單位這邊的，只有「綁定」本身。SAP 也畫在同一條線上：ABAP Dictionary 要求每個 `QUAN` 欄位指定參照的單位欄。

沒綁單位時會在哪裡浮現：

| 路徑 | 是否擲出 |
|------|---------|
| 伺服端存檔捨入（`FormBusinessObject` → `FormExpressionCalculator` → `RoundByKind`） | 是，限數量或重量的計算欄 |
| client 即時計算（`FormLiveComputation`） | 是——而且**不會**被 degrade 吞掉；degrade 是給客戶寫錯運算式用的，不是給設定錯誤用的 |
| `NumericEdit` / `GridControl` 的顯示格式 | 否 |
| 交付 schema（`NumberFormatApplier.Bake`） | 否——數量與重量從不 bake |

這與公司沒有本幣的處理一致：同樣是計算金額時擲、顯示時不擲。執行期的檢查只看得到它要捨入的欄位，所以只輸入、不計算的數量欄沒綁單位不會擲；這類欄位由下方 DefineEditor 的檢查在設計期抓出來。

**相容性**：二進位相容，公開 API 未變。決策記於 [ADR-026](../adr/adr-026-numeric-semantics-rounding.md) 的修訂紀錄。

### 數量與重量的位數不再來自公司

綁定改為必填之後，公司完全退出數量與重量的解析：

| 情況 | 之前 | 現在 |
|------|------|------|
| 該列單位代碼為空 | 公司位數，否則框架預設 | 不捨入——`RoundByKind` 原值返回 |
| 單位代碼不在 `UnitSettings` | 0 | 框架預設（`Quantity` 0、`Weight` 3） |
| 未部署單位主檔 | 公司位數，否則框架預設 | 框架預設 |
| `CompanyInfo.NumberFormats` 裡的 `Quantity`／`Weight` 項 | 供未綁單位的欄位使用 | 不生效 |
| `NumberFormatApplier.Bake` 遇到數量或重量欄 | 未綁單位時以公司位數 bake | 從不 bake |
| 以 `RoundByKind(value, kind, company)` 捨入數量或重量 | 捨到公司或框架位數 | 原值返回（沒有單位代碼） |

**為何單位為空時不捨入**：新增的明細列可能在選單位之前就被計算。捨到一個沒有任何單位選過的位數，會丟掉真正的單位要保留的小數——而且不像金額，沒有本幣可以改拿來解析。

**為何查不到的代碼退框架預設**：與幣別那一側一致，`CurrencySettings` 查不到的代碼退 0.01。`UnitSettings.GetDecimals` 保留它自己「單純查表、查不到回 0」的語意；解析器不再使用它。

**相容性**：二進位相容，公開 API 未變。依賴公司數量位數、透過公司多載捨入數量，或綁定了主檔沒有定義的單位代碼的呼叫端，行為會改變。

## 新增

### `tools/DefineEditor`：單位綁定檢查

`FormSchemaValidator` 在數量或重量欄沒有 `UnitField`，或 `UnitField` 不是同一張表、同樣大小寫的欄時報錯。兩條都對應執行期讀取單位的方式：`FormExpressionCalculator` 從被計算的那一列、以宣告欄名、區分大小寫查找單位欄，所以指到別張表或大小寫不同的單位欄，都會被當成空單位代碼。哪些 kind 需要單位取自 `NumberKindProfile.GetDecimalsSource`，與計算器同一個來源。

新增的 `tests/Bee.DefineEditor.UnitTests` 涵蓋這項檢查，也讓 DefineEditor 進入 CI 建置——在此之前沒有任何 workflow 建置它。non-shipping tool。

## 變更

### `samples/Avalonia.DemoCenter`：數值格式範例改綁單位

`NumberFormatModule` 的數量與重量欄改綁單位欄（PCS、KG），逐列依單位解析位數，因此切換公司不再改變它們的位數。

## 升級指引

沒有 `Quantity` 或 `Weight` 欄的 schema 不需要改。三件事要檢查。

**每個數量或重量欄都綁定同一張表的單位欄。** 在 `FormSchema` 檔中搜尋 `NumberKind="Quantity"` 與 `NumberKind="Weight"`；沒有 `UnitField` 的計算欄，存檔或即時計算時會擲例外：

```xml
- <FormField FieldName="qty" Caption="Quantity" DbType="Decimal" NumberKind="Quantity" />
+ <FormField FieldName="qty" Caption="Quantity" DbType="Decimal" NumberKind="Quantity" UnitField="qty_uom" />
```

單位隱含在語意裡的計數——件數、箱數——比較適合當一般數值欄位：拿掉 `NumberKind`，而不是硬造一個單位欄。

**在程式碼中捨入數量或重量**，改透過攜帶 `UnitSettings` 的 `RoundingContext` 傳入該列的單位代碼：

```csharp
- var qty = NumberFormatResolver.RoundByKind(value, NumberKind.Quantity, company);
+ var qty = NumberFormatResolver.RoundByKind(value, NumberKind.Quantity, ctx, unitCode);
```

公司多載沒有單位代碼，現在會原值返回。

**公司位數表與單位代碼。** `st_company.number_formats_xml` 裡的 `Quantity` 與 `Weight` 項不再生效；留著無妨，位數現在來自 `UnitSettings`。綁定的單位代碼若不在 `UnitSettings` 中，現在會捨到框架預設，`Weight` 由 0 位變成 3 位。
